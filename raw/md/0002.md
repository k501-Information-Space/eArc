**Part 1 — Repository Overview**

K501-AIONARC is a provenance-first archive kernel. Its core purpose is to preserve deterministic lineage: every meaningful state change should be representable as a transition, every transition should be replayable, every reconstructed state should be auditable, and every audit should be reducible into proof, receipt, freeze, and archive artifacts.

Architectural philosophy:

- Prefer deterministic content identity over mutable database identity.
- Treat the journal as authority.
- Treat indexes, projections, graphs, and registries as rebuildable accelerators.
- Separate semantic identity from operational metadata.
- Preserve archive evidence as a chain, not as isolated files.

Ontology vocabulary:

- `Axiom`: root conceptual primitive.
- `Kernel`: root orchestration concept.
- `Frame`: bounded information unit.
- `StateObject`: current state of a frame.
- `Snapshot`: captured state at a transition boundary.
- `Freeze`: immutable frozen snapshot artifact.
- `Proof`: verification result derived from audit facts.
- `Receipt`: durable acknowledgement of proof creation.
- `Audit`: verification of transition, snapshot, freeze, proof, or receipt lineage.
- `Archive`: long-term preservation artifact.

Concept interaction:

```
Axiom
  -> Kernel
      -> Frame
          -> StateObject
              -> Transition lineage
                  -> Snapshot
                      -> Freeze
                          -> Audit
                              -> Proof
                                  -> Receipt
                                      -> Archive
```

The ontology objects are mostly thin Pydantic records today. Runtime meaning lives in modules such as [transition_v2.py (line 10)](/home/matsch/Projekte/k501-aionarc_mirror/src/k501/core/transition_v2.py:10), [journal.py (line 23)](/home/matsch/Projekte/k501-aionarc_mirror/src/k501/storage/journal.py:23), [audit_runtime.py (line 8)](/home/matsch/Projekte/k501-aionarc_mirror/src/k501/core/audit_runtime.py:8), [proof_runtime.py (line 8)](/home/matsch/Projekte/k501-aionarc_mirror/src/k501/core/proof_runtime.py:8), and [archive_runtime.py (line 8)](/home/matsch/Projekte/k501-aionarc_mirror/src/k501/core/archive_runtime.py:8).

Storage philosophy:

- `JournalStore` is authoritative append-only storage.
- `IndexStore` is disposable and rebuildable.
- `ArchiveStore` persists archive payloads as JSON files.
- There is no production database layer yet despite SQLAlchemy being listed as a dependency.

Proof philosophy:

- Proofs are deterministic hashes of validated audit facts.
- Receipts acknowledge valid proofs.
- Archives preserve receipt/proof/state linkage.
- The repository also contains manual proof records in `docs/proofs`, which are historical manifestation records, not runtime-generated proofs.

Archive philosophy:

- Archive artifacts are the preservation endpoint of the proof chain.
- Archive identity derives from receipt/proof/state identity.
- Archive storage exists, but archive navigation and graph-backed reconstruction are incomplete.

**Part 4 — Runtime Spine**

Canonical flow:

```
Transition
  -> Journal
      -> Replay
          -> Projection
              -> Snapshot
                  -> Freeze
                      -> Audit
                          -> Proof
                              -> Receipt
                                  -> Archive
```

Stage details:

|Stage|Input|Output|Invariant|Failure Conditions|
|---|---|---|---|---|
|Transition|before/after state, type, content, provenance|`TransitionV2`|ID must match canonical payload|malformed fields, tampered ID|
|Journal|transition|JSONL record + head|append-only, no duplicate transition ID|duplicate, invalid identity, write failure|
|Replay|ordered transitions|state dict|deterministic fold order|empty stream|
|Projection|ordered transitions|`StateObject`|latest transition defines current state|empty stream, weak/missing fields|
|Snapshot|ordered transitions|snapshot dict|captures transition boundary|empty stream, missing transition|
|Freeze|snapshot|`FreezeArtifact`|freeze ID hashes state/transition/state ID|missing snapshot fields|
|Audit|transitions, optional snapshot/freeze|audit dict|linear state chain, monotonic timestamps, valid provenance references|empty stream, broken lineage, timestamp regression, mismatch|
|Proof|audit|proof dict|proof ID hashes audit facts|invalid audit|
|Receipt|proof|receipt dict|receipt ID hashes proof/state/transition|invalid proof, missing timestamp|
|Archive|receipt|archive dict|archive ID hashes receipt/proof/state|missing receipt fields|

**Part 5 — Lineage Architecture**

Event sourcing: partially implemented.

- The journal is append-only.
- State is reconstructed by replay/projection.
- Indexes are rebuildable.
- Missing: schema migration, event application semantics, concurrency, recovery.

Provenance tracking: partially implemented.

- `TransitionV2.provenance_transition_ids` tracks transition dependencies.
- Audit verifies provenance IDs appear earlier in the stream.
- Missing: multi-stream provenance, external evidence pointers, typed provenance edges.

Audit chains: implemented at basic chain level.

- Audit validates linear state transitions.
- Audit can include snapshot and freeze verification.
- Missing: identity validation inside audit, full freeze hash verification.

Proof chains: partially implemented.

- Proofs are generated from audits.
- Proof graph accepts parent proof IDs.
- Missing: production proof artifact schema and end-to-end proof-to-receipt compatibility.

Graph lineage: embryonic.

- Proof graph topology exists.
- Lineage query exists.
- Traversal is first-parent only.

Archive lineage: partially implemented.

- Archive includes receipt/proof/state/transition IDs.
- Archive index maps archive ID to receipt ID.
- Missing: archive -> receipt -> proof -> graph loader.

Difference between transition lineage and proof lineage:

- Transition lineage is operational state history: how a frame/state changed.
- Proof lineage is evidentiary history: how validations, receipts, and archives depend on prior proofs.

Transition lineage should answer: “How did this state come to exist?”

Proof lineage should answer: “What evidence verifies this state and its preservation chain?”

Limitations:

- Multi-parent proof graphs are represented but not traversed correctly.
- DAG traversal is absent.
- Lineage reconstruction from persisted archive stores does not exist.
- No cycle detection.
- No orphan detection.
- No missing-parent validation.
- No archive-to-proof backtrace.

**Part 6 — Architectural Corrections**

Proposed stack:

```
Archive Store
↓
Archive Index
↓
Receipt Registry
↓
Graph Loader
↓
Proof Graph
↓
Lineage Query
```

This stack is directionally correct, but one refinement matters: Archive Index and Receipt Registry are both lookup structures over persisted artifacts. The Graph Loader should consume them, verify completeness, and build topology.

Correct separation:

- **Graph Loader = reconstruction**
    
    - Reads archives, archive indexes, receipt registry, proof records.
    - Resolves IDs.
    - Detects missing receipts/proofs.
    - Produces normalized graph input.
- **Proof Graph = topology**
    
    - Owns the adjacency structure.
    - Stores `proof_id -> parent proof IDs`.
    - Validates graph-level properties.
- **Lineage Query = traversal**
    
    - Computes ancestors, descendants, roots, paths, subgraphs.
    - Should not load files.
    - Should not know archive storage.

Graph Loader should exist before Proof Graph and Lineage Query in implementation order because Proof Graph needs normalized proof relationships, and Lineage Query needs a graph. Without Graph Loader, the graph layer remains hand-fed test data.

Recommended architecture:

```
ArchiveStore
  -> ArchiveIndexRuntime
      -> ReceiptRegistryRuntime
          -> GraphLoader
              -> ProofGraphRuntime
                  -> LineageQueryRuntime
```

Also add:

```
GraphIntegrityRuntime
  -> validates missing parents, cycles, roots, orphan receipts
```

**Part 7 — Technical Debt**

**Critical**

1. Proof/receipt contract mismatch.
    
    - Impact: canonical runtime spine breaks at `Proof -> Receipt`.
    - Remediation: decide timestamp ownership. Either `ProofRuntime` emits `timestamp_ns`, or `ReceiptRuntime.build()` receives timestamp separately.
2. No end-to-end runtime spine test.
    
    - Impact: unit tests pass while integrated pipeline can fail.
    - Remediation: add test covering transition -> journal -> replay -> snapshot -> freeze -> audit -> proof -> receipt -> archive.
3. Graph Loader missing.
    
    - Impact: archive lineage cannot be reconstructed from persisted artifacts.
    - Remediation: implement loader from archive store/index/receipt registry/proof artifacts.

**High**

4. Duplicate transition models.
    
    - Impact: conceptual drift between v1 and v2.
    - Remediation: deprecate v1 or create migration adapter.
5. Incomplete graph traversal.
    
    - Impact: multi-parent proof lineage is not actually supported.
    - Remediation: implement full DAG ancestors/descendants/path traversal.
6. Missing corruption recovery.
    
    - Impact: journal claims append-only safety but cannot recover from malformed tail.
    - Remediation: use `last_valid_offset`, truncate invalid tail safely, emit `TailCorruptionError` only when recovery is impossible.
7. Missing concurrency control.
    
    - Impact: concurrent writers can corrupt or duplicate journal state.
    - Remediation: file locking or single-writer service.

**Medium**

8. Stale proof documentation.
    
    - Impact: historical proof records become unreliable.
    - Remediation: generate proof docs from current schema/test metadata.
9. Runtime artifacts use untyped dicts.
    
    - Impact: contracts are implicit and fragile.
    - Remediation: add Pydantic models for `AuditArtifact`, `ProofArtifact`, `ReceiptArtifact`, `ArchiveArtifact`.
10. Archive store lacks atomic writes.
    
    - Impact: partial archive files possible.
    - Remediation: temp file + fsync + replace.
11. Audit does not validate transition identity.
    - Impact: caller can audit tampered transition objects if they bypass journal.
    - Remediation: call `IdentityValidatorV2` inside audit.

**Low**

12. Empty README and docs folders.
    - Impact: maintainer onboarding is poor.
    - Remediation: add architecture overview and runtime spine docs.
13. Placeholder subsystems.
    - Impact: architecture appears larger than implementation.
    - Remediation: mark packages as planned or add minimal interfaces.
14. Fixed `/tmp` usage in tests.
    - Impact: possible state leakage.
    - Remediation: use `tmp_path`.
15. Stray untracked file named `ed -n 1,200p` .
    - Impact: repository hygiene.
    - Remediation: remove after confirming it is accidental.

**Part 9 — Maturity Assessment**

Current maturity level: **Experimental Kernel**.

Justification:

- More than a prototype: it has deterministic IDs, append-only journal storage, replay/projection, audit, proof, receipt, archive, graph primitives, and 118 passing tests.
- Not yet a functional archive kernel: the full runtime spine has a known contract break, graph reconstruction is missing, archive navigation is incomplete, and storage is not production-safe.
- Not yet a provenance engine: DAG lineage, retrieval, governance, and robust proof artifacts are incomplete.
- Far from archive operating system: no API, workers, agents, observability, distributed archive, or policy layer.

**Part 10 — Final Architectural Judgement**

K501-AIONARC today is an experimental provenance archive kernel: a compact, deterministic event-sourcing and proof-chain prototype with a strong conceptual spine and early storage/runtime primitives.

It is becoming a lineage-preserving archive engine: a system where state history, proofs, receipts, and archive artifacts can be reconstructed, audited, traversed, and preserved.

The single most important next milestone is an end-to-end typed archive spine:

```
TransitionV2
-> JournalStore
-> Replay/Projection
-> Snapshot
-> Freeze
-> AuditArtifact
-> ProofArtifact
-> ReceiptArtifact
-> ArchiveArtifact
-> ArchiveStore
```

That milestone should include one integration test that proves the whole chain works without hand-injected fields.

Prioritized architectural sequence:

1. Fix `ProofRuntime` / `ReceiptRuntime` contract.
2. Add typed artifact models for audit, proof, receipt, archive.
3. Add end-to-end runtime spine test.
4. Harden journal recovery and archive atomic writes.
5. Implement Graph Loader from archive/receipt/proof artifacts.
6. Upgrade Proof Graph and Lineage Query to real DAG behavior.
7. Generate proof documentation from runtime artifacts instead of maintaining stale manual records.

The core idea is sound. The repository now needs consolidation: fewer parallel concepts, stronger typed contracts, one canonical pipeline, and graph reconstruction from persisted evidence. Once that exists, K501-AIONARC can move from experimental kernel to functional archive kernel.
