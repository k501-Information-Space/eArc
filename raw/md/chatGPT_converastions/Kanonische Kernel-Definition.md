## Ziel des PoC

Ein minimales System, das beweist:

1. **Frames** sind atomar, lockbar, hashbar  
2. **Packs** bündeln Frames reproduzierbar  
3. Ein **Feed (RSS/Atom)** dient als *referenzieller Verteiler* (kein Push, kein Sync-Zwang)  
4. **Import ist manuell** und erzeugt **append-only Logs**  
5. Export/Senden erfolgt **nur durch expliziten User-Act**

```txt

    packs/                  # Pack-Manifeste
    indexes/                # registrierte Indizes
  out/

    exports/                # explizite Exporte (manuell ausgelöst)
  logs/
    basic.log               # append-only, statistics-only möglich
    imports.log             # append-only Import-Register
    exports.log             # append-only Export-Register
```

## PoC-Operationen (manuell, keine Automatik)

### 1) `create-frame`
- erstellt Frame-Datei in `vault/frames/`
- berechnet hash
- schreibt **basic.log** append-only: `FRAME_CREATED`

### 2) `lock-frame`
- setzt `lock: true` (nur wenn noch nicht gelockt)
- loggt `FRAME_LOCKED`

### 3) `build-pack`
- erstellt Pack-Manifest
- pack_hash berechnen
- loggt `PACK_BUILT`

### 4) `export-pack` (explizite User-Aktion)
- kopiert Pack + referenzierte Frames nach `out/exports/<pack_id>/`
- loggt `PACK_EXPORTED`
- **erst danach** darf der Feed einen Link auf dieses Export-Verzeichnis enthalten

### 5) `import-pack` (manuell)
- Import liest Export-Ordner oder remote Download (aber: *nicht automatisch*)
- validiert hash + framenamen + lock-state
- schreibt in `logs/imports.log` append-only
- importiert als neue lokale Objekte (optional: prefix namespace)

- `rules.network_send == explicit_user_action_only`

**Export-Check**
- Exporte nur via `export-pack` (erkennbar am exports.log)

#!/usr/bin/env bash
FRAMES_DIR="/path/to/vault/frames"   # <-- anpassen
INTERVAL=30

start_epoch=$(date +%s)
