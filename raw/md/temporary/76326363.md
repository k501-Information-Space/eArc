1. Grundentscheidung (fest)

  

  

Dateisystem + SQLite

Das ist die beste Logik für eArc.

  

- Dateisystem = Wahrheit
- SQLite = Index
- Kein Ersatz, keine Konkurrenz

3. SQLite-Schema (minimal & stark)

  

  

  

Tabelle: 

artifacts

  

CREATE TABLE artifacts (

  id INTEGER PRIMARY KEY AUTOINCREMENT,

  path TEXT NOT NULL,

  type TEXT NOT NULL,          -- superkorn | frame | pack | superpack | canon

  role TEXT,                   -- ethos | invariant | context | voice

  status TEXT NOT NULL,        -- drafted | fixed | archived

  hash TEXT NOT NULL,

  created_utc TEXT NOT NULL,

  source TEXT,                 -- iarc | external

  UNIQUE(path, hash)

);

  

Tabelle: 

relations

 (optional, später)

  

CREATE TABLE relations (

  from_id INTEGER,

  to_id INTEGER,

  relation TEXT,

  FOREIGN KEY(from_id) REFERENCES artifacts(id),

  FOREIGN KEY(to_id) REFERENCES artifacts(id)

);

  

Tabelle: 

events

 (append-only)

  

CREATE TABLE events (

  id INTEGER PRIMARY KEY AUTOINCREMENT,

  timestamp_utc TEXT NOT NULL,

  event TEXT NOT NULL,

  details TEXT

);

👉 Keine Inhalte in SQLite. Nur Verweise.

  

  

  

  

4. Arbeitslogik (wichtig)

  

  

  

Schreiben

  

  

- Schreiben passiert nur ins Dateisystem
- SQLite wird neu indiziert
- Kein Direkt-Write in DB

  

  

  

Lesen

  

  

- Analyse liest:  
    

- Dateien
- SQLite-Index

-   
    
- Kein Mutieren

  

  

  

  

  

5. Obsidian-Integration (realistisch)

  

  

- Obsidian arbeitet direkt im vault/
- YAML-Header = maschinenlesbar
- Links bleiben normal
- Keine Plugins nötig für Start

  

  

Optional später:

  

- Dataview (nur Lesen)
- Custom Scripts extern

  

  

  

  

  

6. TAT1-Integration (sauber)

  

  

TAT1:

  

- liest SQLite + Vault
- erzeugt:  
    

- feeds/rss.xml
- feeds/atom.xml

-   
    
- kein Push
- kein Netzwerk

  

  

Feeds sind statische Artefakte.

  

  

  

  

7. Analyse-Pipeline (Spirit)

  

  

Reihenfolge:

  

1. Scan Vault
2. Hash & Status prüfen
3. Index aktualisieren
4. Muster erkennen
5. Neue Frames schreiben
6. Event loggen

  

  

Alles append-only.

Diese liegen außerhalb der Datenbank:

- Frames

-   
    

  

  

Kein Rückfluss.
